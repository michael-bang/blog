Ansible Automation Platform MCP server

05/01/2026 - Estimated reading time: 6 minutes — Ansible

Introduction

Generative AI has been a hot topic this past year and we have seen a large range of people taking this new technology in to their everyday life. We are seeing students using ChatGPT, Gemini and the likes to help them do their studies both for good and bad. We are seeing companies that are implementing chatbots to be the first interaction with customers and we are seeing people that are not tech savy utilizing finding easy to get started with. Although LLM’s are good at providing help information it can only do it on what it has been trained on. So if I want to use my chatbot to get the latest in sports, information about new movies or the weather it wouldn’t be able to help. Agentic AI makes this possible and through the use of MCP (Model Context Protocol) it makes it easy to connect your solution with information that the LLM hasn’t been trained on. This can be anything from a database with customer information to web pages, search engines or api endpoints. Agentic AI makes it possible to interact with the “outside world” and use your chatbot to make transactions for you. A lot of solutions are beginning to provide MCP solutions so that you can use your favorite LLM and agent capable solution to interact with these systems and not have to relay on these systems traditional interfaces (UI or CLI based). With the latest version of Ansible Automation Platform (AAP) you now have the posibility to interact with the platform through MCP. In this blog post I will show how you can setup this and use it from VSCode. There are five different areas that are exposed through MCP. I will focus on one of them, but the configuration is the same, but will provide access to different parts of the AAP platform.

Requirements

You need the following:

  • Ansible Automation Platform 2.6 (you can 60 days trail subscription here: https://www.redhat.com/en/technologies/management/ansible/trial). You need to install the MCP part which is at the time of writing in technical preview.
  • A configured LLM that can be used with agents. I’m using granite-3.3-8b-instruct
  • VSCode, Claude or similair client that can provide the chat environment with agent capabilities
  • Both the endpoint hosting the LLM and the AAP MCP endpoint should have valid certificates. Self signed is not recommended.

Installing AAP with MCP container based

Ansible Automation Platform can be installed in a number of different ways.

  • RPM based on RHEL
  • Container based on RHEL using Podman
  • Operator based on OpenShift Container Platform

The latter two includes the MCP server functionality. I have used the container based installation in this blog post.

You can find the official documentation here:

https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.6/html/containerized_installation/deploying-ansible-mcp-server

Install the MCP component in AAP

Installation of the MCP component in AAP require you to add the following to your AAP installation inventory file when you do the installation in the first place or for adding the MCP components (see the documentation on how to run the AAP installation):

[ansiblemcp]
your-fqdn # name of the host where the ansiblemcp component should be installed

[all:vars]
# Ansible
mcp_allow_write_operations=true

The mcp_allow_write operations makes you decide if the mcp component will make it possible to make changes to the platform like running a playbook through the mcp server. You can always decide whether the user accessing AAP through MCP is allowed to do write operations.

After the installation the MCP component will run on port 8448.

Configure a user to be used through MCP on AAP

You can define any number of users in AAP that can be used with the MCP component. The users access to job templates, inventories etc. will corespond to what the MCP client can get access to.

Create a new user in AAP or decide on an existing user that you want to use with MCP.

Log into AAP with that user.

Open the users information in Access Management. Under the API Token create a new API token.

On the “Create API Token” page provide an optional description for the use of the token and a scope. The scope tells if this token can be used to make changes to the platform through this user token.

A write scope will not make it possible to do changes to the AAP platform if you set the mcp_allow_write_operations to false when you did the installation.

Configure the client to use the MCP tools provided through the AAP MCP component

The AAP MCP component provides 6 different toolsets that can be accessed through different uris

Toolset Description Uri
Job management Tools to list and work with job templates /job_management/mcp
Inventory management Tools to query and work with inventories /inventory_management/mcp
System monitoring Tools for retrieving job logs and checking the health of the environment /system_monitoring/mcp
User management Tools to work with users and access /user_management/mcp
Security/compliance Tools that enable the AI agent to act as a security operator /security_compliance/mcp
Platform configuration Tools to tune the platform /platform_configuration/mcp

I’m using the Continue plugin in VSCode. In order to get this to work you need to configure the LLM model that you want to use. I have used the ibm-granite model and configured that as a local configuration.

Access to the MCP server can be configured in different ways. I chose to create a mcp.json file in my ~/.continue/mcpServers. The configuration should look something like this:

{
  "mcpServers": {
    "aapmcp": {
      "type": "http",
      "url": "https://<your fqdn>/job_management/mcp", # Url to the toolset you want to use
      "headers": {
        "Authorization": "Bearer <YOUR TOKEN>"
      }
    }
  }
}

Conclusion

Configuring the MCP component in AAP and getting access to it is fairly simple and you have seen how you can use a prompt to interact with the AAP platform.

When and why would you use this instead of using the traditional AAP APIs or the GUI ?

A growing number of developers and users are turning to LLMs and MCP servers to do their development and here AAP automation can be used within the same context I also believe that troubleshoting could be done through activating job templates from a prompt and then use the LLM to compare outputs or combine it with other information that can be pulled through other MCP tools.
